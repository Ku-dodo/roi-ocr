# 이미지 OCR 도구

여러 이미지에 색상과 Tag / UI ID가 있는 여러 ROI를 일괄 적용하고 최대 4배로 확대하여 EasyOCR로 문자열을 추출하는 Windows 데스크톱 프로그램입니다. 결과는 실행 파일 위치의 `result/` 폴더에 CSV로 저장됩니다.

## 개발 환경 준비

Python 3.10 환경에서 검증했습니다. CPU 전용 PyTorch를 먼저 설치하여 CUDA 라이브러리가 배포물에 들어가지 않도록 합니다.

```powershell
python -m venv .venv-release
.\.venv-release\Scripts\python.exe -m pip install --upgrade pip
.\.venv-release\Scripts\python.exe -m pip install torch==2.14.1+cpu torchvision==0.29.2+cpu --index-url https://download.pytorch.org/whl/cpu
.\.venv-release\Scripts\python.exe -m pip install -r requirements.txt
```

선택한 언어 모델이 없으면 상단 톱니바퀴 설정에서 `모델 자동 다운로드`를 체크한 뒤 OCR을 실행해 `models/` 폴더로 다운로드할 수 있습니다. 이 옵션의 기본값은 꺼짐입니다. 배포본에도 모델 파일은 포함하지 않으므로 모델을 내려받을 때 인터넷 연결이 필요합니다.

## 실행

```powershell
.\.venv-release\Scripts\python.exe .\main.py
```

1. `이미지 추가`를 누르거나 등록된 파일 영역으로 드래그 앤 드롭하여 여러 이미지를 등록합니다.
2. 목록에서 기준 이미지를 선택하고 미리보기에서 왼쪽 드래그로 ROI를 여러 개 추가합니다. 새 영역에는 구분 색상과 `ui_1`, `ui_2` 등의 Tag가 자동 지정됩니다. 미리보기 아래 표의 `Tag / UI ID`를 편집하여 `user_name` 등 원하는 ID를 지정하고, 색상 셀을 더블클릭하면 색상을 변경할 수 있습니다. Tag는 비어 있거나 다른 ROI와 중복될 수 없습니다. 같은 좌표와 Tag가 등록된 모든 이미지에 적용됩니다.
3. 상단 `기본 인식 언어`에서 언어명 또는 코드로 검색해 기본 언어를 선택합니다. 파일 목록의 `인식 언어` 셀을 클릭하면 파일별로 다른 언어를 지정할 수 있습니다. 여러 파일을 선택한 뒤 `선택 파일 언어 변경`을 누르면 한 번에 변경할 수 있습니다. 영어가 아닌 언어에는 영어가 자동으로 함께 적용됩니다. 필요한 모델이 없다면 톱니바퀴 설정에서 `모델 자동 다운로드`를 체크합니다.
4. 톱니바퀴 아이콘에 마우스를 올리거나 클릭하면 설정 팝업이 열립니다. `선택 이미지 배율`에서 `1x`, `2x`, `4x` 중 확대 배율을 지정합니다. 전처리 확대 배율은 최대 4배로 제한됩니다. 여러 행을 선택하면 배율이 함께 적용됩니다.
5. 같은 팝업에서 터미널이나 콘솔 화면은 `콘솔 전처리 ON`을 선택해 색 번짐을 제거할 수 있습니다. 이 모드에는 `1x` 배율을 권장합니다. 팝업 밖으로 마우스를 옮기거나 바깥을 클릭하거나 `Esc`를 누르면 설정 팝업이 닫힙니다.
6. `OCR 실행`을 누릅니다. 미리보기 아래의 통합 표(`색상 / Tag / UI ID / 영역 / 상태 / 결과`)에서 ROI별 진행 상태와 인식 결과를 확인할 수 있습니다. 파일 목록에서 다른 이미지를 선택하면 해당 이미지의 결과로 바뀝니다. 미리보기와 표 사이의 경계를 드래그하면 높이를 조절할 수 있습니다. 결과 셀에 마우스를 올리면 전체 문자열, 신뢰도 또는 오류 내용을 확인할 수 있습니다.
7. `result/ocr_result_날짜_시간.csv`에서 `UI ID / 언어 / 추출 문자열 / 상태 / 신뢰도`를 확인합니다. UI ID는 ROI의 Tag이며 파일 이름은 CSV에 기록하지 않습니다. 이미지별·ROI별로 한 행이 생성되므로, 같은 UI ID의 한국어와 영어 결과를 언어 코드로 구분할 수 있습니다. 언어에는 해당 파일의 인식에 사용한 주 언어 코드(`ko`, `ch_sim`, `en` 등)가 기록되고, 신뢰도는 EasyOCR 평균 신뢰도를 백분율로 표시합니다.

CSV 상태는 `Done`, `Fail`, `Need Review`로 구분합니다. 이미지 읽기나 OCR 처리 중 오류가 발생하면 `Fail`, 정상 처리됐지만 추출 문자열이 비어 있거나 신뢰도가 없거나 80% 미만이면 `Need Review`, 나머지는 `Done`입니다. 80% 기준은 초기 검토 기준이며, `Done`이 실제 문자열의 정확성을 보장하지는 않습니다. 검토 기준은 `src/ocr_app/domain/models.py`의 `REVIEW_CONFIDENCE_THRESHOLD`에서 변경할 수 있습니다. 상태는 CSV에 기록하며 화면의 처리 완료/실패 집계는 기존과 같습니다.

파일 이름을 대신해 ROI Tag를 UI ID로 사용하므로 `CSV 파일 이름에 확장자 포함` 설정은 제거했습니다. 등록된 파일 목록에는 이미지 구분을 위해 원본 파일 이름을 계속 표시합니다.

ROI 프리셋은 미리보기 상단의 `저장`으로 이름을 붙여 저장할 수 있습니다. 예를 들어 `Login_Scene`을 저장한 뒤, 다른 언어의 로그인 화면을 등록하고 목록에서 해당 프리셋을 선택해 `불러오기`를 누르면 같은 좌표·Tag·색상을 재사용합니다. 같은 이름으로 저장하면 해당 프리셋을 갱신하며 `삭제`로 저장된 항목을 제거할 수 있습니다. 프리셋 삭제는 현재 화면에 적용된 ROI를 제거하지 않습니다.

프리셋은 실행 파일 위치의 `presets/roi_presets.json`에 저장되어 재실행 후에도 사용할 수 있습니다. 언어, 이미지, OCR 결과는 저장하지 않습니다. 좌표는 원본 픽셀 기준으로 적용하므로 같은 해상도와 화면 배치의 이미지에 사용합니다. 다른 PC로 옮길 때는 `presets` 폴더도 함께 복사하면 됩니다. 사용자 프리셋 파일은 Git 및 배포 ZIP에 포함하지 않습니다.

새 파일은 `기본값 · 한국어`처럼 현재 기본 언어를 따라갑니다. 상단 기본 언어를 변경해도 파일에 직접 지정한 언어는 유지됩니다. 파일별 언어 선택에서 `기본값 사용`을 고르면 다시 상단 설정을 따릅니다. 실행 전에 등록된 파일에 필요한 모든 언어 모델을 확인합니다.

멀티 ROI는 `OCR 실행` 시 등록된 모든 이미지에 일괄 적용됩니다. 이미지 크기가 ROI보다 작으면 이미지 경계 안의 영역만 처리합니다. ROI 내부를 오른쪽 클릭하면 해당 ROI만 삭제됩니다. 겹친 영역에서는 가장 위에 보이는 ROI 하나만 삭제하며, ROI 밖을 오른쪽 클릭하면 아무것도 삭제하지 않습니다. `ROI 전체 삭제` 버튼으로 모든 영역을 제거할 수 있습니다. 화면에서 OCR을 실행하려면 ROI를 하나 이상 지정해야 합니다. 한 ROI의 처리 오류가 다른 ROI 처리를 중단시키지 않으며, 화면의 완료·실패 집계는 이미지 단위입니다.

미리보기에서 마우스 휠로 커서 위치를 중심으로 확대·축소할 수 있습니다. 확대 후에는 휠 버튼(가운데 버튼)을 누른 채 드래그하거나 스크롤바로 이동하고, 왼쪽 더블클릭으로 전체 이미지에 맞춥니다. 왼쪽 드래그는 ROI를 추가합니다. ROI는 원본 이미지의 픽셀 좌표로 유지되며, 확대·축소하거나 이동한 화면에서 새로 지정해도 원본 좌표로 저장됩니다. 미리보기 확대·축소는 OCR 처리용 `선택 배율`에 영향을 주지 않습니다.

한국어를 포함한 언어 모델은 `모델 자동 다운로드`를 체크한 상태에서 OCR을 실행할 때 다운로드됩니다.

## 배포 빌드

`build.ps1`은 제3자 라이선스 수집과 PyInstaller `onedir` 빌드를 순서대로 실행합니다. OCR 모델 파일은 빌드에 포함하지 않습니다.

```powershell
.\build.ps1
```

완성된 진입점은 `dist/OCRTool/OCRTool.exe`입니다. GitHub Release에 올릴 ZIP과
SHA-256 파일은 `dist/OCRTool-0.1.0-windows-x64.zip` 및 `.sha256`으로 생성됩니다.
버전을 변경하려면 `build.ps1 -Version 0.2.0`처럼 실행합니다. `models` 폴더는 첫 OCR
실행 시 자동으로 생성됩니다.

배포본의 OCR 파이프라인을 화면 없이 점검하려면 다음 진단 명령을 사용할 수 있습니다. 성공하면 배포 폴더의 `result/`에 CSV가 생성됩니다.
이 진단 모드는 전체 이미지를 처리하며 UI ID를 `full_image`로 기록합니다.

```powershell
.\dist\OCRTool\OCRTool.exe --smoke-ocr ".\sample.png"
```

## GitHub 공개와 Release

저장소에는 소스 코드만 커밋합니다. `.gitignore`에 `dist/`, `build/`, 가상환경,
OCR 모델 및 결과 파일이 포함되어 있습니다.

버전 태그를 올리면 GitHub Actions가 테스트와 Windows 빌드를 실행하고 ZIP과
SHA-256 파일이 첨부된 GitHub Release를 자동으로 생성합니다.

```powershell
git tag v0.1.0
git push origin v0.1.0
```

태그의 `v` 뒤 값은 `build.ps1`에 전달되는 배포 버전입니다. 같은 태그는 다시 사용할
수 없으므로 다음 배포에서는 `v0.1.1`, `v0.2.0`처럼 올립니다.

## 구조

```text
src/ocr_app/
├─ domain/          순수 데이터 모델과 규칙
├─ application/     OCR 처리 유스케이스와 인터페이스
├─ infrastructure/ OpenCV, EasyOCR, CSV 구현체
└─ presentation/   PySide6 UI와 백그라운드 작업
```

`main.py`는 구현 로직을 포함하지 않고 애플리케이션을 조립하고 시작하는 진입점으로만 사용합니다.
